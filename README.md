# statutewatch — 法规/标准条文多次发布的身份归并、版本归档与条文级实质差异

运行栈：Python 3.11+ 标准库 `sqlite3` + `httpx` + `pytest`（离线，无需联网）

## 运行方式
```text
make run                  # 旧通用记录流水线（兼容基线，落 records 表）
make run-regulations      # 法规批次流水线（身份归并→归档→条文级 diff）
make test                 # 全量测试（46 个，含幂等/事务/回滚/兼容）
```

## 四类对象严格分离
| 对象 | 表 | 语义 |
| --- | --- | --- |
| 法规对象 | `regulations` | 同机关同文号的同一份法规；换下载地址、重新扫描不改变身份 |
| 内容版本 | `versions` / `clauses` | 一次实质内容快照；内容指纹相同即复用同一版本 |
| 采集批次 | `batches` / `batch_versions` | 一次扫描动作；与版本多对多，复扫只加关联不复制版本 |
| 附件 | `attachments` / `attachment_events` | 附属文件；附件变化独立留痕，不冒充正文修改 |

身份归并优先级：①机关+文号强键 → ②机关+规范标题次强键 → ③同名不同机关、
④缺标题/机关标识：后两者进入 `identity_pending` 并保留标题、机关、文号、URL、
批次等原始依据，确认前不并入任何法规对象。

## 处理流水线（法规）
`loader → canonicalize（别名映射/损坏检测）→ normalizer（版式清理+条文切分）
→ identity（身份归并/待确认）→ fingerprint（条款+文档+附件指纹）
→ archive（单事务版本归档，触发 diff）→ sqlite`

- **版式噪声清理**：只去全角空格、制表符、页眉页脚、独立行号、重复空白与软连字符；
  数字、单位、否定词、标点和条文边界完整保留。每条条文同时存 `raw`（原始片段）与
  `clean`（清理文本）。
- **OCR 不确定**：`??`、`[?]`、`<unclear>`、`□` 等标记原样保留并打标，绝不猜补修正；
  含标记的结论可信度最高只给 `medium`。
- **缺页/解析失败**：`【缺页…】` 拆为独立 Gap 证据，缺口相邻条文位置记入
  `gap_positions_json`；这些位置上的删除只能报 `low` 可信度并注明"需人工回查"，
  绝不报告确定删除。
- **差异类型**：`reorder / split / merge / added / removed / replaced / cosmetic`。
  条号锚定先识别重排；1:n、n:1 按包含度识别拆分/合并；残余块只信任条款指纹对齐，
  无可靠对齐依据时按增删报告而非猜测替换。数字/单位/否定词变化逐 token 标注，
  每条结论的 `evidence_json` 都是可回查的 `fragment_id`。
- **指纹的定位**：仅作快速判同与对齐辅助。同指纹同文本是正常复用；同指纹不同文本
  标记 `collision=1` 并强制退回文本比对——碰撞、附件变化、规则升级都不能让真实
  修改消失。
- **事务边界**：一个批次在单个事务内处理，任一文档损坏（`download_error`/空正文/
  哈希不符）或处理异常即整批回滚，批次标 `failed`，无半份档案；失败后可用同
  `batch_id` 修复重试，已提交批次输入不可变。同输入重跑幂等空转。
- **规则版本**：`config.RULE_VERSION`（当前 `2026.1`，基线 `2026.0`）随版本与差异
  行落库，`rule_meta` 存变更日志；可显式指定旧规则重新复现历史结论。
- **证据 GC**：`garbage_collect_blobs` 只删除不被附件 sha256、条文 fragment_id、
  差异证据引用的过期原始件；仍在证据链上的一律保留。

## 取舍说明（自动归并 / 差异可信度 / 资源开销）
1. **自动归并偏保守**：强键（文号）缺失时不做激进模糊匹配，宁可进 `identity_pending`
   人工确认，也避免把不同机关的同名法规错误合并——误合并的代价高于多一条待办。
2. **差异可信度三档**：完整对齐给 `high`；OCR 不确定或相似度配对给 `medium`；
   缺页/解析失败相邻给 `low`。`low` 删除不是结论而是待核查线索，避免把采集缺陷
   误报成法规废止。
3. **指纹只辅助不定论**：条款指纹用 sha256，计算与存储开销低；但任何指纹判同都
   可被文本复核推翻，碰撞显式留痕。代价是极端碰撞下退回逐条比对，CPU 开销上升，
   换取结论可解释、可回查。
4. **资源开销**：条文 `raw/clean` 双份与证据索引占用额外存储，换来每条差异可回查
   原始片段；GC 用引用计数控制原始件膨胀。离线单文件 SQLite，无外部服务依赖。
